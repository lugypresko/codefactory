# split_even drops the remainder when n does not divide total

## Summary

`cfdemo.split_even(total, n)` is supposed to split a non-negative integer `total` into `n` non-negative integer parts that **sum back to `total`** and differ by at most 1.

When `n` does not divide `total`, the current implementation returns `n` copies of `total // n` and silently drops `total % n`. The parts then sum to less than `total`.

## Reproduction

```python
from cfdemo import split_even
print(split_even(10, 3))  # today: [3, 3, 3]  (sum 9, not 10)
```

## Expected

The returned list has length `n`, every element is a non-negative integer, elements differ by at most 1, and `sum(parts) == total`. For the example above one valid result is `[4, 3, 3]` (the remainder may be distributed on any of the parts, as long as those constraints hold).

The existing regression tests only cover cases where `n` already divides `total` (or n==1, or total==0), so they stay green while this bug remains.
